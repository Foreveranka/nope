# Recipe workflow verification

A stage is completed only after an actual recorded check; this checklist is not evidence of completion.

- The browser reads a synthetic supplier/customer export locally.
- A public operation recipe is selected; private records and other columns are not embedded in its parameters.
- Real garbling creates fresh labels and an immutable request. Output pairs remain local and encrypted at rest when a workspace job is saved.
- The HTTP endpoint receives only approved typed recipes and encoded input, validates origin/content-type/size/topology, and actually evaluates the circuit.
- Numeric sentinel/missing, clamp-only missing preservation and recipe order match independent examples, including every byte where feasible.
- Text leading/trailing spaces, internal spaces, exact byte capacity, case changes and digit masking match the declared character policy without truncation.
- Unselected UTF-8 columns, row ordering and quoting are preserved; unsupported input is rejected before dispatch.
- A second provider cannot fetch another provider's task or delivery. The selected provider cannot accept the buyer's delivery.
- Response nonce, program, input and output hashes plus decoder label membership are checked before local display.
- Reloaded local decoder works; wrong job/version/nonce/program/ciphertext does not.
- A real browser displays before/after and optional download, not a predetermined timer or placeholder result.
- V1 jobs remain readable and executable. Existing direct testnet payment flow is not relabelled escrow.
- Deployment packages only allowlisted assets, no runtime/environment/decoder/customer files.

No item here replaces independent security audit, malicious-party security, an execution SNARK or a general private LLM.
