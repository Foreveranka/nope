# V2 local synthetic selection API

This is a real local MP-SPDZ computation with centralized **synthetic** witnesses.
It is not an independent-operator deployment, a chain finality check, an execution
proof, a payment flow, or an enforcement mechanism against repeated selections.
Only files under `mpc/` are owned by this implementation.

## Order and callable

Prepare FHE artifacts if needed → prepare immutable intent/precommitments → create
registry job → submit all bids → close registry → **MPC selection** → buyer selects
and starts actual execution attempt → FHE evaluation. The selection manifest
contains **no attempt binding**. In particular, do not call `begin_attempt` merely
to manufacture an MPC context. The existing fixed registry executor role is
bound in the intent separately from the eventual selected provider.

```python
from mpc.v2 import (
    build_intent, prepare_synthetic, registry_config,
    build_selection_manifest, manifest_digest,
)
from mpc.run_v2 import run_prepared  # run_selection is the same callable

intent = build_intent(
    network_domain_hash=network_hash, registry_account=contract, buyer=buyer,
    roster=sorted_bidders, qualified=[True, True, True], fixed_fee=0,
    bid_deadline_ns=bid_deadline_string, result_deadline_ns=result_deadline_string,
    spec_hash=spec_hash, circuit_hash=prepared_fhe_server_hash,
    key_hash=prepared_fhe_evaluation_key_hash, input_hash=prepared_fhe_input_hash,
    output_policy_hash=policy_hash, registry_executor=fixed_registry_executor,
)
prepared = prepare_synthetic(intent, budget=100, prices=[90, 80, 95])
config = registry_config(prepared)  # registry-ready byte arrays + U64 strings
# Orchestrator creates job(config), submits prepared.commitments[1:4], closes,
# and independently retrieves its Closed view. MPC performs no transactions.
manifest = build_selection_manifest(prepared, closed_job)
public_selection_digest = manifest_digest(manifest)
result = run_prepared(prepared, closed_job, timeout=600, port=17400)
found, client_id, price, total = result["output"]["buyer"]
winner = prepared.intent["roster"][client_id - 1] if found else None
# Only now may the buyer select/start the actual registry execution attempt.
```

Hashes passed to `build_intent` are lowercase hex32 or NEAR JSON byte arrays.
Deadlines must be canonical decimal U64 **strings**. Roster must contain exactly
three sorted distinct canonical accounts, excluding buyer; qualification flags
are actual booleans. `registry_config` and `build_selection_manifest` copy their
outputs. `PreparedSynthetic` is frozen: canonical intent bytes, commitment tuple,
private amount tuple and salt tuple. `.intent` returns a fresh dictionary;
`.intent_bytes` is the binary intent and `.context_hash` is its SHA-256 hex.
Secret fields are excluded from `repr`. Do not serialize this witness object.
The helper knows all inputs and therefore is explicitly unsuitable as a real
sealed-bid coordinator.

`python3 -m mpc.sample_v2` shows public preparation/configuration. Add `--run` for
actual local MPC over **fabricated registry metadata**. The main orchestrator may
instead supply its actual local NEAR sandbox Closed snapshot. This MPC module
checks snapshot consistency, not the sandbox itself or network provenance.

## Exact versioned encoding

V1 remains in `auction.py` and `programs/sealed_procurement.mpc`, using its original
descriptor-hash commitment. V2 uses `v2.py` and a separate
`programs/sealed_procurement_v2.mpc`. Client version dispatch is explicit
(`--codec-version 2`); a v2 manifest never falls through to v1 interpretation.
The compiled SHA-256 circuit uses the v2 precommit context and the **same private
amount/salt bits** used for selection. No host precheck replaces that comparison.

The strict intent dictionary has exactly these fields:

```text
version profile networkDomainHash registryAccount buyer roster qualified fixedFee
bidDeadlineNs resultDeadlineNs specHash circuitHash keyHash outputPolicyHash
inputHash registryExecutor intentNonce selectionRound mpcProgramHash upstream
```

`version=2`, profile=`sealed-cheapest-3-spdz2k-v2`, upstream is the pinned MP-SPDZ
commit. `intentNonce` and `selectionRound` are separately generated random
32-byte public nonces, frozen **before** commitments. Optional explicit nonces
are available only to reproduce synthetic codec vectors. `mpcProgramHash` is the
SHA-256 of the v2 circuit source; it is distinct from the FHE `circuitHash`.

`encode_intent` concatenates, in order:

```text
"VEIL-INTENT-v2\0" || uint8(2)
|| string(profile) || hash32(networkDomainHash)
|| string(registryAccount) || string(buyer)
|| uint8(3) || string(roster[0]) || string(roster[1]) || string(roster[2])
|| bool8(qualified[0]) || bool8(qualified[1]) || bool8(qualified[2])
|| uint64_be(fixedFee) || uint64_be(bidDeadlineNs) || uint64_be(resultDeadlineNs)
|| hash32(specHash) || hash32(circuitHash) || hash32(keyHash)
|| hash32(outputPolicyHash) || hash32(inputHash)
|| string(registryExecutor) || hash32(intentNonce) || hash32(selectionRound)
|| hash32(mpcProgramHash) || string(upstream)
```

Here `string` is ASCII with uint32 **big-endian** byte length; `bool8` is exactly
00/01; `hash32` is 32 raw bytes. This codec is independent of JSON key order.
It contains no job hash, bidset root, attempt hash or commitment.

```text
P = SHA256(encode_intent(intent))
C_i = SHA256("VEIL-MPC-v2\0" || P || uint8(i) || uint64_be(amount_i) || salt32_i)
```

IDs 0/1/2/3 mean budget/roster slots 0/1/2. Salts are independently generated
private random 32-byte values. Amount ranges and auction semantics are unchanged
from v1: budget 0..10^12, prices 1..10^12, public fee 0..10^12, first price,
lowest eligible price, ties resolved by lowest slot. Every slot must participate.

## Closed selection manifest

Exact fields:

```text
version: 2
kind: "closed-job-selection"
intent: <strict intent above>
precommitContext: <P hex>
commitments: [C_0, C_1, C_2, C_3]
closedJob: <full Closed registry JSON job>
selectionRound: <the intent's selectionRound hex>
mpcBuild: {upstream: <pin>, circuitSourceHash: <intent's mpcProgramHash>}
```

Validation independently re-encodes the registry's actual **Borsh v1** job hash
and full three-entry bidset root, checks every config field against intent,
checks budget and bid commitments/roster, closure time/deadlines and buyer, and
requires state `Closed`, attempt `"0"`, null attempt binding, and no receipts.
The original job-view schema is accepted, as is its explicit paired extension
`selected_executor:null, attempt_binding_version:null`. A partially supplied
pair or nonnull preselection value is rejected. Unknown fields fail closed.
Unqualified bidders still require valid commitments and private inputs. Missing
bid slots are rejected, not silently padded or removed.

```text
M = SHA256("VEIL-SELECTION-v2\0" || canonical_json(manifest))
```

Canonical JSON is sorted keys, compact separators, ASCII, no NaN. Every client
revalidates the complete manifest and local circuit source pin, then sends all
256 bits of M to **each** TLS-pinned operator. Each operator compares against
its compiled public manifest constants before receiving private inputs. Operators
therefore reject one client presenting another otherwise valid Closed snapshot.
TLS certificate pinning, live active preprocessing, MAC checks, private output
checks, post-check completion markers and transient-key cleanup remain required.

The API result contains `output`, `manifestHash`, `codecVersion`, source/runtime
identities, public bindings and `selectedExecutor`. The latter is a local output,
not an on-chain selection transaction. `registryCodecBindingVerified:true` means
codec/config checks passed. `chainFinalityVerified:false`,
`durableSelectionReplayGuard:false`, and `independentOperators:false` remain
explicit. `nearBindingVerified:false` is retained from the harness to avoid
implying it fetched or authenticated chain state.

A matching hash alone authenticates neither buyer identity nor registry state.
The caller must establish snapshot provenance/finality and durable authorization
for a selection round. The precommitted nonce does not enforce one-shot use.
No one can claim an attempt exists or the registry verifies an MPC winner just
because this local circuit returned a winner. A later execution artifact may
bind the resulting actual attempt; it cannot be inserted retroactively here.

## Verification commands

```sh
python3 -m unittest discover -s mpc/tests -v
python3 -m mpc.verify_v2
python3 -m mpc.run_local --case cheapest  # retain actual v1 behavior
python3 mpc/verify_tls.py
```

The expensive v2 verification runs a good case, a changed private bid, a changed
private budget, and a client presenting a different valid public manifest. Bad
commitment tests keep all registry commitments unchanged and alter private
inputs only. A passing rejection requires all three **native** party logs to
contain `invalid sealed input` (or `manifest context mismatch` for the public
manifest case). Timeout, compile errors and generic transport errors do not count.
Both success and abort must remove all transient keys and `Player-Data` directories.
